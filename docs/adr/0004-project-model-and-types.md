# ADR-0004: 工程数据模型、类型共享与编辑策略

- 状态：已采纳
- 日期：2026-11-16

## 决定

1. **唯一模型定义在 Rust**（`engine-core/src/model.rs`），时间以“拍”为单位。用 serde 序列化成 JSON；用 ts-rs 自动生成 TypeScript 类型到 `packages/engine-web/src/types/`，禁止手写重复类型。
2. **UI 持有工程文档**，负责编辑和撤销/重做（不可变数据 + 补丁，计划用 Immer）。引擎是“渲染器”，接收工程快照。
3. **v1 编辑策略：每次编辑都整体重载**。实测 8 轨 4 千音符的工程，解析 + 编译约 0.5 ms，完全可接受。
4. 教程里的“和弦进行”本身就是一个 MIDI 片段（Clip），以后可以直接拖进编曲时间轴。
5. 工程文件格式：`.chordlab` = zip（`project.json` + `samples/`），支持导入/导出备份，避免只存浏览器存储导致数据丢失。

## 后果

- ⚠ 超过约 3 万个音符时，整体重载会超过 5 ms。需要在大工程出现前（E5 编曲阶段）实现：Web 端在 Worker 中编译事件表再传入 worklet；或改为按轨道增量更新。已记入待办。
- 模型字段变更必须带默认值（`#[serde(default)]`），保证旧工程文件可读。
