## 回顾

**保留**
- TDD 的“先红后绿”提交顺序：每个缺陷都先有能复现它的测试（#42 引擎层 5→1 个声部、UI 层 33→3 个 NoteOn），修复后不会回归。
- PO 的 UX 测试很有价值：键盘自动重复、音乐时值（回声不在拍上）、信息清晰度这三类问题，自动化测试都没覆盖到。
- 两端（浏览器、桌面）端到端测试让“同一界面驱动两种引擎”这个架构假设每次提交都被验证。

**改进**
- **并行 PR 的隐性冲突**：#45 与 #46 各自 CI 全绿，但合在一起编译不过（新增必填字段 `delay_beats`）。改进：仓库规则集开启“合并前分支必须与 main 同步”，让 CI 总是验证合并后的代码；同一模块的 PR 依次合并。
- **测试依赖偶然常量**：#49 的一个测试暗含了旧的固定延迟时间，#46 一改就失败。改进：测试只断言它要保护的性质（“清零阈值不截断可闻回声”），时间点从被测对象本身推导。
- 自检的“会话峰值”无法区分一次性尖峰与持续负载 → 已增加“最近 1 秒峰值”。

**尝试**
- 新增“音乐正确性”测试类别：节拍对齐、时值、力度等，和功能测试并列（#43 的回声对齐测试是第一个）。
- 每个可交互功能都配键盘与长按的 e2e 场景；UX 测试脚本固定包含“长按 / 快速连按 / 切到别的窗口”。
- 预览版里提供一个“已知问题”清单，减少 PO 重复反馈。
